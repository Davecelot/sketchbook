## Differences and action plan

All behavioral and visual differences are already recorded as `realizations.web.drift` entries (trigger 28 vs 32px, `collapsible=none` on narrow, drawer focus wrap, drawer exit motion, truncation without ellipsis, focus return after a link, `aria-controls` reflection, `href=""` default). No unrecorded code divergence found.

1. Contract text vs code, breakpoint (contract side, low): `openQuestions` Q4 answer says the token is inlined into media queries "and the script constant at build time". The provider actually reads `--sb-sidebar-breakpoint` from computed style at runtime (SB-0109/SB-0110 as briefed). Contract section 7 ("styles and script read the same token") is compatible, so the code is fine; update the Q4 answer and the Realizations > Web paragraph to say "script reads the same token through the CSS variable at runtime". Fix belongs in the contract.
2. `contract.json` `decisions` lists SB-0007, SB-0009, SB-0101 only; the contract depends on SB-0109 and SB-0110 (md cites them). Add both to `decisions` (contract).
3. SB-0101 "Watch out" still says "the breakpoint is a literal because tokens cannot be used in media queries", which is superseded by SB-0109/0110 and by Q4. SB-0101 is `proposed`; a human decides whether to amend it or leave it and rely on the newer decisions (accepted decisions must not be edited; propose a superseding note otherwise).
4. Contract text vs code, link focus (informational): section 10 / Q5 says only that a link closes the drawer; code returns focus to the trigger. Recorded as drift; consider promoting it into section 9 as the contract rule, since it is the desired behavior.
5. Ambiguous (human call): `FOCUSABLE` in `Sidebar.ts` omits `summary`, `[contenteditable]` and `audio/video[controls]`; header/footer content is arbitrary, so the Tab wrap could miss such a first or last control. Either record it in the drift entry for focus wrap or extend the selector.
6. Open, not a parity defect: Q6 (VoiceOver/NVDA manual pass) is owed before beta; Figma realization "Not realized yet" (contract says so); status stays draft.

## Verdict

Matches contract, with a small needs-contract-update: the code satisfies the contract; items 1 to 4 are text updates to the contract and the decision log, and item 5 is a judgment call. No code fix required.

Status (2026-11-15): already fixed (contract.json decisions list SB-0109 and SB-0110; Q4 and Realizations say the provider reads the token at runtime; SB-0101 Watch out updated; link focus return is in section 9; FOCUSABLE includes summary, contenteditable and media controls).
