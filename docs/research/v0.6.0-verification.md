# Sketchbook v0.6.0 verification

On November 23, 2026, we tested the published Sketchbook CLI, then reran selected workflows on an unpublished follow-up candidate. The results show what worked in the tested environments. They do not establish that the agent guidance saves time or money.

## Published package

We installed `@usesketchbook/cli@0.6.0` from npm and ran it in disposable projects on macOS with Node 26.13.1 and npm 12.2.3. The release source was [`95f55109`](https://github.com/Davecelot/sketchbook/commit/95f55109). The installed CLI and the release checkout were tested separately.

| Check | Result |
| --- | --- |
| Start a project, adopt an existing app, upgrade from v0.5.1, and repair a missing skill | Passed. Dry runs wrote nothing. Adoption preserved the app's source files and existing script; it added one check script. |
| Change a foundation token and rebuild its outputs | Passed. `check` rejected deliberately stale CSS, then passed after `generate`. |
| Git pre-commit hook | Passed with a valid contract, rejected a broken one, and passed again after the fixture was restored. |
| Node 22 smoke test on macOS | Node 22.23.5 passed `init`, install, `add button`, `check`, and `generate`. Linux was not tested. |
| Release checkout checks and browser suite | All 28 deterministic checks passed. `npm run test:harness` reported 348 passes, 8 skips, and no failures. `npm run verify` reached the runner timeout during Playwright; a separate six-worker run against the built Storybook passed all 1,014 tests. |
| Approval and test-first evidence | In a disposable Button fixture, the installed CLI refused a red run before approval and rejected a stale approval. Chromium then recorded one expected failure out of 19, followed by 19 passes with the same spec. `sketchbook evidence ready` advanced the plan to `ready`. |

In seven warm runs in the same small installed project, median wall time was 1.13 seconds for `check` and 0.65 seconds for `generate`. These timings describe that fixture on that machine, not a speed comparison. To reproduce the browser stage, run `npm run build-storybook`, then `CI=true npm run test:component -- --workers=6` on a machine that can handle six workers.

### Findings that led to the follow-up

The published-package pilot used Claude Code 2.1.330 with `claude-sonnet-5-5`, medium effort. It ran 19 task trials, including four permission replays, and 10 short probes. Claude Code reported $3.92 in model cost. In the new-component task, the CLI-only run drafted files but didn't register the component; the full-guidance run stopped when the `add` workflow and the contract-author skill disagreed about registration. Those two outcomes led to the guidance change.

All three seeded QA setups found the six known defects in their single trials. The full-guidance report made more evidence-shaped claims, but also incorrectly reported missing local assets. That finding prompted separate human labels for verified findings and false positives.

In the matched startup probe (three runs per setup), median input including cached tokens was 10,956 for files and the CLI and 15,906 with Claude guidance, a difference of 4,950 tokens. This measures the cost in context of starting a session for one short prompt, not task efficiency or billed cost.

## Unpublished follow-up

The follow-up was tested on the v0.6.0 source plus the workflow and test fixes, and in a local tarball built from that source. The tarball used the v0.6.0 version string but was not the npm artifact. Its SHA-256 was `7fb6f18d84df3f3bc396e70b77618d2633ea7ae6145546875ae85969b4e14b87`. The benchmark runner was updated separately to give both UI setups the same prebuilt browser assets.

| Check | Result |
| --- | --- |
| `npm run test:harness` | 349 passed, 8 skipped, 0 failed. |
| `npm run lint`, `npm run typecheck`, `npm run typecheck:harness`, and `sketchbook check` | Passed. The deterministic checks reported the existing allowed literal in `Table.scss`. |
| `SKETCHBOOK_TEST_OPENCODE_LIVE=1 node --test harness/test/opencode-live.test.mjs` | Passed with OpenCode 2.3.2 and a local mock model. This verifies discovery, skill loading, and CLI invocation, not model adherence. |
| `npm run test:wall` | Passed. The fixture generated Figma scripts locally with a dummy key; it did not sync a real Figma file. A separate test checked the no-key path. |
| Browser-enabled benchmark grader tests | 3 passed. They cover permission denials, verified QA findings versus false positives, and keyboard reachability, submission, and component loading. |
| Installed-candidate component scaffold | An unknown name was refused without writes. After registration, the dry run still wrote nothing. The real scaffold passed checks and stopped at `stage: plan` with no tests, implementation, or approval record. |

Run `npm run build:harness` before the standalone OpenCode test. Run the grader tests with `SKETCHBOOK_TEST_BENCHMARK_BROWSER=1 node --test docs/research/value-benchmark/scripts/grading.test.mjs`. The [benchmark runner](value-benchmark/README.md#rerunning-on-current-packages) describes the templates, permissions, and grading.

### Matched Claude smoke tests

These rows use Claude Code 2.1.330 with `claude-sonnet-5-5` at medium effort, one trial per setup and task. Both setups used the same local candidate and prompt. For the UI replay, both received the same prebuilt bundle and token stylesheet.

| Task | Setup | Independently verified result | Wall time | Reported cost |
| --- | --- | --- | --- | --- |
| Draft Health Dot | Files + CLI | One registry entry, valid contract and plan at `stage: plan`; no approval, tests, or implementation | — | $0.439 |
| Draft Health Dot | Files + CLI + Claude guidance | Same outcome | — | $0.441 |
| Settings page | Files + CLI | Worked offline; all three controls and Save worked by keyboard; 0 axe findings in either theme; did not use the recommended checkbox | 34 s | $0.177 |
| Settings page | Files + CLI + Claude guidance | Same outcome | 23 s | $0.135 |

The first UI pair had restricted tool access: one page referenced a bundle that the agent could not build. It is not included in the table. The replay still recorded permission denials (five with files and CLI, one with the full setup); the browser grader verified the delivered page separately. Across the two planning trials and both UI pairs, Claude Code reported $1.66 in model cost.

These runs do not establish an efficiency gain, cross-provider model performance, or WCAG conformance. Live Figma sync and visual parity were not tested. Repeat the matched runs with more trials and a non-Claude model before making broader claims.
