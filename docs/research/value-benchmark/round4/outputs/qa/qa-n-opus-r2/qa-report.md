# QA report: out/settings.html

- Line 28: `<sb-switch name="push">` has no `label`, which the Switch contract requires (`props.label.required: true`). The switch has no accessible name (WCAG 4.1.2), and the description is not a name. Fix: add `label="Push notifications"`.
- Line 27: `tone="success"` is not a Switch prop. The contract defines only label, hideLabel, description, error, name, value, checked, required, disabled and size, so the attribute does nothing. Fix: remove `tone="success"`.
- Line 29: `<sb-toggle>` is used as a form setting, which the Toggle contract lists as an anti-pattern ("Toggle for a setting saved with a form": it submits nothing, `formAssociation.value: false`). `name`, `label` and `description` are not Toggle props, so "digest" is never submitted. Fix: replace it with `<sb-switch name="digest" label="Weekly digest" description="A summary every Monday">`, or `sb-checkbox` (see the next finding).
- Line 29: `<sb-toggle>` has no default-slot text or `aria-label`, so the button has no accessible name (Toggle `content.default.required: true`, WCAG 4.1.2). Fix: replace it as described above, or if a toggle really is intended, put the label text in its slot.
- Lines 27-29: several independent switches that only take effect after a Save button match the Switch contract anti-pattern "Several independent options in a list needing a Save" (switches imply immediate effect). Fix: use `sb-checkbox` for these form fields, or drop the Save button and apply each switch as soon as it changes.
- Line 34: a raw `<button class="save">` with hand-written styles (line 15) is used instead of the library's Button. It has no design-system focus ring, hover or disabled states. Fix: use `<sb-button type="submit">Save</sb-button>` and remove the `.save` rule.
- Line 13: `.hint` uses the hard-coded color `#d33` instead of a token. Red also makes neutral help text look like an error. Fix: use `color: var(--sb-color-muted-foreground)`.
- Line 13: `var(--sb-font-size-small)` does not exist in `generated/css/tokens.css`, so the font size falls back to the inherited size. Fix: use `var(--sb-font-size-sm)` (or `--sb-font-size-caption`).
- Line 12: `var(--sb-space-17)` does not exist (the space scale has 0–6, 8, 10, 12 and 16), so the grid `gap` is invalid and the fields have no spacing. Fix: use a semantic spacing token such as `var(--sb-space-stack-loose)`.
- Lines 10, 15: page CSS uses raw foundation spacing steps (`--sb-space-6`, `--sb-space-2`, `--sb-space-4`) instead of semantic tokens. Pages are meant to use semantic tokens only (kits contract in `docs/harness.md`). Fix: use semantic tokens, e.g. `--sb-space-inset-surface` for body padding (and use `sb-button` for the button padding).
- Line 23: `<sb-card-title>` holds plain text, so the page has no heading in the document outline. The Card contract says the title is only a visual heading and needs a real heading element inside it. Fix: `<sb-card-title><h1>Notification settings</h1></sb-card-title>`.
- Lines 7-8: the page loads tokens and components from `node_modules/sketchbook/` (the engine's reference build) instead of this design system's own outputs. Brand changes in `brand.config.json` and local components won't show. Fix: link `../generated/css/tokens.css` (plus `../generated/css/fonts.css`, which is also missing) and this package's built bundle (`../dist/sketchbook.js` after `npm run build`).
