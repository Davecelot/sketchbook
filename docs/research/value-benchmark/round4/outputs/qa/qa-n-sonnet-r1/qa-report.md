# QA report: out/settings.html

- `<sb-switch name="push" description="Alerts on your phone">` has no `label`; the Switch contract makes `label` required, since it is the only accessible name (external `<label for>` can't reach the inner input). Fix: add `label="Push"` (or similar).
- `<sb-switch ... tone="success">` uses a `tone` attribute that the Switch contract does not define (props: label, hide-label, description, error, name, value, checked, required, disabled, size). Fix: remove `tone="success"`, or add the prop to the contract first.
- `<sb-toggle name="digest" label="Weekly digest" description="A summary every Monday">` uses `name`, `label` and `description`, but the Toggle contract only has `variant`, `size`, `pressed` and `disabled`. The text would not render and the form value would not be named. Fix: use `<sb-switch>` for an on/off setting with a label and description, or put the text in the toggle's content and use its `pressed` prop.
- `.fields { gap: var(--sb-space-17) }`: `--sb-space-17` does not exist (generated scale stops at `space-16` and skips some values), so the gap is dropped. Fix: use an existing token such as `var(--sb-space-4)`.
- `.hint { color: #d33 }` is a hard-coded colour that bypasses the tokens and will not follow dark mode or the brand. Fix: use `var(--sb-color-destructive)`, or a muted foreground token if this is only a hint. A hint reading "Changes apply after you save." is not an error.
- `.hint { font-size: var(--sb-font-size-small) }`: `--sb-font-size-small` is not defined (the scale is `xs`, `sm`, `base`, ...), so it falls back to the inherited size. Fix: use `var(--sb-font-size-sm)`.
- The Save control is a plain `<button class="save">` with page-local CSS, even though the library has `sb-button` (and the page already uses the card and switch components). Fix: replace it with `<sb-button type="submit">Save</sb-button>` and delete the `.save` rule. Check the Button contract for form submission support first.
- The `.hint` paragraph is a bare `<p>` styled by page CSS where the system has typography/field components, so the page's text style will drift from the library. Fix: use the library's typography component (or `sb-field` description) for the hint, tokens only.
- `<sb-card-title>` is the only heading for the card and the contract says it is a visual heading, not part of the document outline; the page has no heading element. Fix: put a real `<h1>`/`<h2>` inside `sb-card-title`.
- The three controls sit in a `<div class="fields">` with no grouping, so assistive tech gets no shared name for the set. Fix: wrap them in `<fieldset><legend>` (or use `sb-field`) naming the group, e.g. "Notify me by".
