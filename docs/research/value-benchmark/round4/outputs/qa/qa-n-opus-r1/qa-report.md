# QA report: out/settings.html

- Line 28: `<sb-switch name="push">` has no `label`, which the switch contract requires (it is the accessible name, and an external `<label for>` cannot name the inner input). Fix: add `label="Push notifications"`.
- Line 27: `tone="success"` is not a prop of `sb-switch` (the contract has label, hideLabel, description, error, name, value, checked, required, disabled, size). Fix: remove `tone="success"`.
- Line 29: `sb-toggle` is used as a form field, but its contract has `formAssociation.value: false`, so it submits nothing; `name`, `label` and `description` are not toggle props, so "digest" never reaches FormData and the control has no accessible name (it names itself from slot text). Fix: replace it with `<sb-switch name="digest" label="Weekly digest" description="A summary every Monday"></sb-switch>` (or `sb-checkbox`).
- Lines 27–34: switches inside a form with a Save button go against the switch contract's aiHints anti-pattern ("Several independent options in a list needing a Save → Checkbox"), because switches imply the change applies immediately. Fix: use `sb-checkbox` for these options, or drop the Save button and apply each switch on change.
- Line 34: a hand-styled native `<button class="save">` stands in for the library's Button. Fix: use `<sb-button type="submit">Save</sb-button>` and delete the `.save` rule on line 15.
- Line 12: `var(--sb-space-17)` does not exist in `generated/css/tokens.css` (the spacing scale stops at 16; there is no 17), so the `gap` is invalid and the fields have no spacing. Fix: use an existing token such as `var(--sb-space-6)` or `var(--sb-space-field-gap)`.
- Line 13: `var(--sb-font-size-small)` does not exist in the tokens, so the hint falls back to the inherited size. Fix: use `var(--sb-font-size-sm)`.
- Line 13: the hint color is a hard-coded literal `#d33` instead of a semantic token, so it ignores the theme and dark mode. Fix: use `var(--sb-color-muted-foreground)`.
- Lines 13 and 31: the informational hint "Changes apply after you save." is shown in red, which looks like an error. Fix: give it muted styling (`--sb-color-muted-foreground`) or move the text into `<sb-card-description>` inside `sb-card-header`.
- Lines 7–8: the page loads tokens and components from the engine package (`../node_modules/sketchbook/...`) rather than this design system's own build (package `ui-a3`: `generated/css/tokens.css`, `dist/sketchbook.js`), so brand and token changes made here never show up on the page. Fix: point to `../generated/css/tokens.css` and `../dist/sketchbook.js` (after `npm run build`).
- Line 15: `.save` uses `--sb-radius-control`, `--sb-color-primary` and `--sb-space-*` directly, outside any component and with no focus style, which reimplements Button's tokens and drops its `:focus-visible` ring. Fix: covered by switching to `sb-button` (remove the rule).
