# QA report: out/settings.html

- Line 28: `<sb-switch name="push">` has no `label`, which the Switch contract marks required (it is the accessible name, and `<label for>` can't reach the inner input), and the console warns about the empty label. Fix: add `label="Push notifications"` (keep `description`).
- Line 27: `tone="success"` is not a Switch prop. The contract defines only `label`, `hide-label`, `description`, `error`, `name`, `value`, `checked`, `required`, `disabled` and `size`, so the attribute is ignored. Fix: remove `tone`, or add a `tone` prop to the Switch contract first.
- Line 29: `<sb-toggle>` is used as a form field with `name`, `label` and `description`. Toggle's contract has only `variant`, `size`, `pressed` and `disabled`. It is not form-associated and has no label or description, so "Weekly digest" never renders and `digest` is never submitted. Fix: use `<sb-switch name="digest" label="Weekly digest" description="A summary every Monday">`, which is form-associated and has those props.
- Line 12: `var(--sb-space-17)` is not a token in `generated/css/tokens.css`, so the `gap` is invalid and the fields collapse together. Fix: use an existing token such as `var(--sb-space-4)` or `var(--sb-space-stack-md)`.
- Line 13: `color: #d33` is a hard-coded literal, outside the token layers and not theme-aware (dark mode and contrast are unchecked). Fix: use `var(--sb-color-destructive)`, or a muted foreground token if this is a neutral hint.
- Line 13: `var(--sb-font-size-small)` does not exist (the scale is `-sm`, `-xs` and so on), so the hint falls back to the inherited size. Fix: use `var(--sb-font-size-sm)`.
- Lines 13, 31: the hint "Changes apply after you save." is styled as an error/destructive message but is neutral help text. Fix: use a neutral muted colour token, not red.
- Line 34 and lines 15, 34: the Save action is a raw `<button class="save">` with hand-written CSS (padding, radius, colours) that duplicates `sb-button`. It also has no hover, focus-visible or disabled states and no focus ring. Fix: replace it with `<sb-button type="submit">Save</sb-button>` and delete the `.save` rule.
- Line 20: the `<form>` has no `action`, `method` or submit handling, and no accessible name. Fix: add `aria-labelledby` pointing at the card title (give it an `id`) and the real `action`/`method`.
- Lines 22-23: the page title is an `<sb-card-title>`, so the page has no `<h1>` or heading landmark. Fix: put a heading element inside the card title (or give it `role="heading" aria-level="1"`) so assistive tech can navigate to it.
- Lines 10-11: the page sets its own layout in a `<style>` block, including `body` grid centring with `min-height: 100vh`, which clips or clashes at narrow or zoomed viewports. Fix: use the settings kit/page pattern in `src/patterns/` rather than ad-hoc page CSS.
