# QA report: out/settings.html

- Line 12: `.fields` uses `gap: var(--sb-space-17)`, which is not defined in `generated/css/tokens.css` (the scale stops at `--sb-space-16`), so the gap is invalid and the fields collapse together. Fix: use an existing token such as `var(--sb-space-4)` or `var(--sb-space-6)`.
- Line 13: `.hint` hardcodes `color: #d33`, which bypasses the semantic tokens and will not follow the theme or dark mode. Fix: use `var(--sb-color-muted-foreground)` for a neutral hint, or `var(--sb-color-destructive)` if it is meant as an error.
- Line 13: `.hint` uses `var(--sb-font-size-small)`, which does not exist (the scale has `--sb-font-size-sm` and `--sb-font-size-caption`), so the declaration is dropped. Fix: use `var(--sb-font-size-sm)`.
- Line 28: `<sb-switch name="push">` has a `description` but no `label`, so the native input has no accessible name (the `NativeControl` empty-label warning fires). Fix: add `label="Push notifications"`.
- Line 27: `tone="success"` is not a property of `sb-switch`, which only has `size`, `value`, `checked`, `hide-label`, `error`, `label`, `description`, `name`, `disabled` and `required`, so the attribute is ignored. Fix: remove `tone`.
- Line 29: `<sb-toggle>` is used as a form field with `name`, `label` and `description`, but `sb-toggle` has only `variant`, `size`, `pressed` and `disabled`. It is not form-associated, so it never submits `digest`. It also shows no label or description text, and the toggle's accessible name comes from its text content. Fix: use `<sb-switch name="digest" label="Weekly digest" description="A summary every Monday">`, or put the label text inside `<sb-toggle>` and drop `name`/`description`.
- Line 34: The Save action is a raw `<button class="save">` styled by hand in line 15 instead of the library component. Fix: use `<sb-button type="submit">Save</sb-button>` and delete the `.save` rule.
- Line 15: `.save` has no `:focus-visible` style or disabled/hover states, so keyboard focus may be invisible. Fix: use `sb-button`, which provides them (see the previous finding).
- Lines 21-36: The settings use hand-rolled `.fields` layout and a `.hint` paragraph instead of the `sb-field`/`sb-field-group` and `sb-field-description` components. Fix: wrap the controls in `<sb-field-group>` and use `<sb-field-description>` for the hint.
- Line 31: The "Changes apply after you save." hint is not linked to the form controls or the button, so assistive tech does not announce it. Fix: give it an `id` and reference it from the form (or use `sb-field-description` inside the group).
- Lines 7-8: The tokens stylesheet and script load from `../node_modules/sketchbook/...`, but `generated/css/tokens.css` and `dist` are what this project builds. Fix: confirm the path resolves from `out/`, or link `../generated/css/tokens.css`.
- Lines 20-37: The `<form>` has no accessible name and no `action`/`method`, and the card title is a generic `sb-card-title` rather than a heading, so the page has no `<h1>` and the form has no landmark label. Fix: add `aria-labelledby` on the form pointing at an `id` on the title, and render the title as a heading level 1.
