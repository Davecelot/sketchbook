# QA report: out/settings.html

- Line 28: the second `<sb-switch name="push">` has no `label`, which the Switch contract requires, so the switch has no accessible name (WCAG 4.1.2). Fix: add `label="Push notifications"`.
- Line 29: `<sb-toggle>` is used as a form field. The Toggle contract has no `name`, `label` or `description` props and is not form-associated (`formAssociation.value: false`, so it submits nothing), and its default slot is empty, so it has no accessible name. Fix: use `<sb-switch name="digest" label="Weekly digest" description="A summary every Monday">` (or `sb-checkbox`).
- Line 27: `tone="success"` is not a prop of `sb-switch` (props are label, hide-label, description, error, name, value, checked, required, disabled, size). Fix: remove `tone="success"`.
- Lines 27–34: switches are combined with a Save button, which is a listed Switch anti-pattern ("several independent options in a list needing a Save", because switches imply immediate effect). Fix: use `sb-checkbox` for these fields, or keep the switches, apply each change immediately and drop the Save button and the hint.
- Lines 15 and 34: a raw `<button class="save">` is styled by hand instead of using the library Button, so it misses the Button's hover, focus-ring and disabled states and its tokens. Fix: replace it with `<sb-button type="submit">Save</sb-button>` and delete the `.save` rule.
- Line 12: `var(--sb-space-17)` does not exist in `generated/css/tokens.css` (the space scale stops at 16, plus semantic steps), so the `gap` is invalid and the fields have no spacing. Fix: use an existing token such as `var(--sb-space-6)` or `var(--sb-space-stack-md)`.
- Line 13: `color: #d33` is a hard-coded literal instead of a token. Red also signals an error for what is neutral help text. Fix: `color: var(--sb-color-muted-foreground)`.
- Line 13: `var(--sb-font-size-small)` does not exist (the defined tokens include `--sb-font-size-sm` and `--sb-font-size-caption`), so the hint falls back to the inherited size. Fix: use `var(--sb-font-size-sm)`.
- Line 23: `<sb-card-title>` is only a visual heading (Card contract: no role and not in the outline), and the page has no `<h1>`. Fix: `<sb-card-title><h1>Notification settings</h1></sb-card-title>`, as the Card contract recommends.
- Lines 7–8: the page loads tokens and components from `../node_modules/sketchbook/...` (the engine's reference copy) instead of this design system's own outputs, so local brand and token changes are not reflected. Fix: link `../generated/css/tokens.css` and this package's built bundle (`dist/sketchbook.js`, exported as `./bundle`).
