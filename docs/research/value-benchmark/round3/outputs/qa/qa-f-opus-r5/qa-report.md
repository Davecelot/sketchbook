# QA report: out/settings.html

- Line 27: `sb-switch` has no `tone` attribute (the contract's props are label, hide-label, description, error, size, name, value, checked, required, disabled), so `tone="success"` does nothing. Fix: remove `tone="success"`.
- Line 28: the "push" `sb-switch` has no `label`, which the contract requires as its visible label and accessible name, so the switch has no accessible name. Fix: add `label="Push notifications"` (or a similar label; use `hide-label` if it must not be visible).
- Line 29: `sb-toggle` is a pressable button for settings that take effect immediately. It is not a form field and has no `label`, `description` or `name` props, so "Weekly digest" renders as an empty button, has no name and is not submitted with the form. Fix: use `<sb-switch name="digest" label="Weekly digest" description="A summary every Monday">` (or `sb-checkbox`, see the next finding).
- Lines 27-34: the switch contract says "Don't use a switch for something that needs a Save to take effect; use Checkbox", but these switches sit in a form with a Save button and the hint "Changes apply after you save". Fix: use `sb-checkbox` for these fields, or keep the switches, apply each change immediately and remove the Save button and hint.
- Line 12: `--sb-space-17` is not a defined token (the spacing scale ends at `--sb-space-16`), so `gap` is invalid and the fields have no space between them. Fix: use a defined token such as `--sb-space-field-gap` or `--sb-space-stack-md`.
- Line 13: `--sb-font-size-small` is not a defined token, so the hint falls back to the inherited size. Fix: use `--sb-font-size-sm`.
- Line 13: the hint uses the hard-coded color `#d33`, which bypasses the tokens, does not change in dark mode, and makes plain help text look like an error. Fix: use `color: var(--sb-color-muted-foreground)`.
- Lines 15 and 34: Save is a hand-styled native `<button class="save">` instead of the design system's button, so it has none of the system's focus ring, size, typography or hover states. Fix: replace it with `<sb-button type="submit">Save</sb-button>` and delete the `.save` rule.
- Line 23: `sb-card-title` has no semantic role and the page has no heading at all, so screen-reader users have no page heading to navigate by. The card contract says to put a real heading inside the title. Fix: use `<sb-card-title><h1>Notification settings</h1></sb-card-title>`.
- Lines 7-8: the page loads tokens and components from `../node_modules/sketchbook` (the harness package) rather than this project's own build, so it does not render this team's components or brand tokens from `src/` and `generated/css/tokens.css`. Fix: point the stylesheet at `../generated/css/tokens.css` and the script at this package's built bundle.
