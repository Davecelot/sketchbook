# QA report: out/settings.html

- `sb-switch name="push"` has no `label`, which the Switch contract requires as its accessible name, so the control is unnamed for screen readers (WCAG 4.1.2). Fix: add `label="Push notifications"`.
- `sb-switch ... tone="success"`: Switch has no `tone` prop (the only variant is `size`), so the attribute does nothing. Fix: remove `tone="success"`.
- `sb-toggle name="digest" label="Weekly digest" description="…"`: Toggle has no `name`, `label` or `description` props, is not a form field (`formAssociation.value: false`, so it submits nothing) and gets its name from slot text, which is empty here. The result is an unnamed button whose value is lost on Save, which is the contract's "Toggle for a setting saved with a form" anti-pattern. Fix: replace it with `<sb-checkbox name="digest" label="Weekly digest" description="A summary every Monday">` (or the same control used for the other settings).
- The settings are on/off switches but only take effect after Save ("Changes apply after you save."). That matches the Switch contract's anti-pattern "Several independent options in a list needing a Save" (switches imply an immediate effect). Fix: use `sb-checkbox` for the email, push and digest options, or apply each switch immediately and drop the Save button.
- `<button type="submit" class="save">` is a hand-styled native button with page CSS instead of the design system's Button. Fix: use `<sb-button type="submit">Save</sb-button>` and delete the `.save` rule.
- `.fields { gap: var(--sb-space-17) }`: `--sb-space-17` does not exist in tokens.css (the numeric scale stops at `--sb-space-16`), so the gap is invalid and the fields have no gap between them. Fix: use `var(--sb-space-field-gap)` (or a `--sb-space-stack-*` token).
- `.hint { font-size: var(--sb-font-size-small) }`: `--sb-font-size-small` does not exist, so the font size falls back to the inherited size. Fix: use `var(--sb-font-size-sm)` (or `--sb-font-size-caption`).
- `.hint { color: #d33 }` is a hard-coded literal instead of a token, and it shows neutral help text in an error red. Fix: use `color: var(--sb-color-muted-foreground)`.
- The page loads `tokens.css` but not `fonts.css`, so `--sb-font-family-body` names a font that is never loaded (Storybook imports `fonts.css` before the tokens). Fix: add `<link rel="stylesheet" href="../node_modules/sketchbook/generated/css/fonts.css">` before the tokens link.
