# QA report: out/settings.html

- `.fields` uses `gap: var(--sb-space-17)` (line 12), and no `--sb-space-17` token exists (the scale jumps from 16 to the named stack tokens), so the gap is dropped and the switches touch. Fix: use an existing token such as `var(--sb-space-field-gap)` or `var(--sb-space-stack-md)`.
- `.hint` uses `font-size: var(--sb-font-size-small)` (line 13), and that token doesn't exist, so the text falls back to the inherited size. Fix: use `var(--sb-font-size-sm)` (or `--sb-font-size-caption`).
- `.hint` hard-codes `color: #d33` (line 13), a literal outside the token system that won't follow dark mode. It also shows a neutral note in an error-like red. Fix: use `color: var(--sb-color-muted-foreground)` (or `--sb-color-destructive` if it really is an error).
- `<sb-switch ... tone="success">` (line 27): `tone` is not a switch prop (the contract has label, hideLabel, description, error, name, value, checked, required, disabled, size), so the attribute does nothing. Fix: remove `tone="success"`.
- `<sb-switch name="push" description="Alerts on your phone">` (line 28) has no `label`, so the control has no accessible name and triggers the component's empty-label warning. Fix: add `label="Push notifications"`.
- `<sb-toggle name="digest" label="Weekly digest" description="…">` (line 29): `sb-toggle` is a pressed-state button, not a form field. It has no `name`, `label` or `description` props, it submits nothing (`formAssociation.value: false`), and the toggle contract lists "Toggle for a setting saved with a form" as an anti-pattern. The digest setting is lost on save and the visible text is missing. Fix: replace it with `<sb-checkbox name="digest" label="Weekly digest" description="A summary every Monday">` (or `sb-switch`).
- The settings are switches gathered under a Save button (lines 27–34). The switch contract's anti-pattern "Several independent options in a list needing a Save" says to use a checkbox, because a switch suggests the change applies immediately. Fix: use `sb-checkbox` for the three settings, or keep the switches and drop the Save step so changes apply right away.
- The Save control is a raw `<button class="save">` styled by hand in page CSS (lines 15 and 34) instead of the library's `sb-button`, so it has no focus ring, hover, disabled or loading states, and no size or density tokens. Fix: `<sb-button type="submit">Save</sb-button>` and delete the `.save` rule.
- The page has no heading: `sb-card-title` adds no role, and the card contract says to put a real heading inside it when the card belongs in the document outline (line 23). Fix: `<sb-card-title><h1>Notification settings</h1></sb-card-title>`.
