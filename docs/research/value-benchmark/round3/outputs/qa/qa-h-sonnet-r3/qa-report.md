- `<sb-switch name="push" description="Alerts on your phone">` has no `label`; label is required in the switch contract (the control has no accessible name and the library warns on an empty label). Fix: add `label="Push notifications"`.
- `<sb-switch ... tone="success">` uses a `tone` attribute that the switch contract does not define (props are label, hide-label, description, error, name, value, checked, required, disabled, size), so it does nothing. Fix: remove `tone="success"`, or add a `tone` prop to the switch contract first.
- `<sb-toggle name="digest" label="Weekly digest" description="A summary every Monday">` uses `name`, `label` and `description`, which the toggle contract does not have (props are variant, size, pressed, disabled). It is an action button that submits nothing, so the setting is never saved with the form and it has no visible text. Fix: use `<sb-switch name="digest" label="Weekly digest" description="A summary every Monday">`, since this is an on/off setting in a form.
- `.fields { gap: var(--sb-space-17) }` uses a token that does not exist (generated tokens have `--sb-space-0` to `--sb-space-16`, with gaps), so the declaration is invalid and the fields get no spacing. Fix: use an existing step such as `var(--sb-space-4)`.
- `.hint { font-size: var(--sb-font-size-small) }` uses a token that does not exist (the scale has `caption`, `body`, `base`, `control` and similar), so the size falls back to inherited. Fix: use `var(--sb-font-size-caption)`.
- `.hint { color: #d33 }` is a hard-coded colour on neutral help text. It bypasses tokens and theming (it breaks in dark mode, and the contrast is unchecked), and red implies an error. Fix: use a semantic text token such as `var(--sb-color-muted-foreground)`, or the destructive token only if this is a real error.
- `<button type="submit" class="save">` with custom `.save` CSS re-implements `sb-button`, so it gets no variant, size, focus-visible ring or disabled states from the design system. Fix: replace it with `<sb-button type="submit">Save</sb-button>` and delete the `.save` rule.
- `.actions` is a hand-made flex wrapper for the footer button. Fix: drop the `<div class="actions">` and rely on `sb-card-footer` layout, or use `sb-button-group` if actions are grouped.
- `<sb-card-title>` is plain text and the page has no real heading, so the page has no `<h1>`/heading in the outline (the contract says the card title is only visual). Fix: put `<h1>` inside `sb-card-title`.
- The form has no accessible name and the `.hint` is not associated with any control. Fix: add `aria-label="Notification settings"` to `<form>` and tie the hint to the controls with `aria-describedby`, or use `sb-field` description slots.
