**Status:** contract `draft`, and the checks pass (C1, C2, A1, T6, X1, R1). This plan has no owner approval. No owner was available on 2026-11-12, and the session asked for every question to be answered with its recommendation and recorded. ## Scope
- **In:** `sb-switch`, one on/off setting with these props:
  - `label`, `hide-label`, `description`, `error`
  - `size` (`default`, `sm`)
  - `name`, `value`, `checked`, `required`, `disabled`

  It is form-associated from the first implementation: FormData, reset, state restore, disabled fieldset, `required` validity and `<label for>` activation. It works from the keyboard (Space toggles, Enter submits) and fires composed `input`/`change`.
- **Out:**
  - an indeterminate state
  - a readonly state
  - an "off value"
  - a `lg` size
  - a label-before layout (that belongs to Field composition)
  - the Figma realization (later sync)

## Tokens
The component tokens are in `contract.json` → `tokens`. They alias only existing semantic tokens, so no new semantic token is needed:
- size: `size.switch.*`, `size.icon.default`/`sm` for the thumb, `space.switch.inset`
- shape: `radius.pill`
- color: `color.input`, `color.primary`, `color.background`, `color.primary-foreground`, `color.destructive`, `color.ring`
- other: `opacity.disabled`, `motion.*`

Contrast was verified by T6 in light and dark. Every pair meets its target; the lowest is the off thumb on the off track, at 4.18:1 in dark mode against a 3:1 target. `generated/tokens/component.tokens.json` and `generated/css/tokens.css` were rebuilt from the contract, and the rebuild only added the Switch tokens.

## Accessibility approach
- **Inner control:** a native `<input type="checkbox" role="switch">` with a native `<label for>` in the same shadow root. Space toggles natively. Enter calls `form.requestSubmit()` (SB-0009).
- **ARIA:** the description and error go in `aria-describedby`. `aria-invalid` is set while invalid. The error is a persistent polite live region. An `error` sets `customError`.
- **Focus and contrast:** a 3px solid focus ring on `:state(focus-visible)`, drawn around the track. The off track is 3:1 and the thumb is at least 3:1 against its track.
- **Mirroring and motion:** the thumb travels toward the inline end when on, using logical properties, so it mirrors in RTL. Its transition is removed under `prefers-reduced-motion`.
- **Target size:** the label row is part of the click target, and the 12px gap meets the WCAG 2.5.8 spacing exception.

## Test plan (test-first)
Write the stories and the spec first. Run `npm run test:component -- tests/switch`, check that every test fails for the right reason (the element is not defined yet), and record that. One test per rule:
1. Has role `switch` and the `label` as its name; `hide-label` keeps the name; the label has the same font size for both sizes.
2. Clicking the label, the track or the thumb toggles it; checked is on, unchecked is off (`aria-checked` true/false, never mixed).
3. Space toggles. Enter submits the enclosing form and does not toggle. Tab moves focus in and out. The keyboard focus ring is visible and a mouse click does not show it.
4. `input` then `change` fire once per user toggle, are composed and are read on `document`. Neither fires when `checked` is set in code or on `form.reset()`.
5. Track and thumb dimensions: `default` 32×20 with a 16px thumb, `sm` 24×16 with a 12px thumb. The thumb is at the inline end when on, and mirrored under `dir="rtl"`.
6. The off and on tracks paint differently. The transition duration is 0 under reduced motion.
7. Description and error are in the accessible description. `aria-invalid` is set when invalid. The error text is in the live region.
8. FormData:
   - nothing while off; `name=on` while on
   - a custom `value` is submitted
   - a `change` listener reading FormData sees the new value
9. `form.reset()` restores the `checked` attribute default, both from on and from off.
10. Disabled:
    - `<fieldset disabled>` disables it, keeps its own `disabled` attribute unset, and leaves it out of FormData
    - re-enabling the fieldset restores it
    - a `disabled` switch cannot be toggled and is not submitted
11. Required:
    - `required` and off is `valueMissing`, `checkValidity()` is false and submission is blocked
    - turning it on makes it valid
    - an aria-hidden asterisk is shown
    - it is invalid after blur
12. `error` sets `customError` and blocks submission; clearing `error` restores validity.
13. A `<label for>` outside the component toggles it.
14. Form state restore puts back the checked state.
15. A dev warning is logged once when `label` is empty.
16. axe reports no violations on every story.

Then implement the smallest code that turns them green, and finish with `npm run check`, `npm run typecheck`, `npm run test:component`, the review-rangers review and the parity audit before `beta`.

## Risks
- **Screen readers:** `role="switch"` on a checkbox input is announced as on/off by current Chromium, Firefox and WebKit, but older screen-reader and browser pairs may fall back to "checkbox". Mitigation: a manual VoiceOver and NVDA pass in the a11y audit before `stable` (Q10).
- **Form owner:** the inner input has no form owner, so Enter and validity rely on the mixins. The existing Checkbox tests show this works, and the spec repeats them.
- **Dark mode:** the off thumb differs from the visual reference (recorded as drift).
- **Engine install:** this install of the `sketchbook` engine has no `harness/cli/` folder, so `npm run check` and `npm run generate` cannot start, and check G1 cannot load. The other checks were run directly against the engine modules and pass. Reinstall the engine before implementation.

## Open questions (answered with the recommendation, 2026-11-12)
| # | Question | Answer (recommendation taken) |
| --- | --- | --- |
| Q1 | Native control: a checkbox input with `role=switch`, or a button with `aria-checked`? | **Checkbox input with role=switch.** Native toggling, `required` validity and disabled come free. |
| Q2 | Does Enter toggle (APG: optional) or submit? | **Enter submits; only Space toggles.** This is consistent with every form control here (SB-0009). |
| Q3 | Is `checked` reflected? | **No.** The attribute is the reset default. |
| Q4 | What is submitted while off? | **Nothing.** `value` is sent only while on, like a native checkbox. |
| Q5 | Which two sizes? | **`default` (32×20/16) and `sm` (24×16/12)**, taken from `size.switch.*`. The label text does not change. |
| Q6 | Is `label` required? | **Yes**, with `hide-label` to hide it visually. |
| Q7 | Where is the label, and which way does the thumb go in RTL? | **The label goes after the switch.** When on, the thumb is at the inline end and mirrors in RTL. |
| Q8 | Indeterminate or readonly? | **Neither.** A switch has only on and off. |
| Q9 | Does the thumb animate? | **Yes**, over the fast duration, and instantly under reduced motion. |
| Q10 | Manual screen-reader pass? | **It goes in the a11y audit before `stable`.** |
