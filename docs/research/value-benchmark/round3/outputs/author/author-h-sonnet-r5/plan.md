# Plan: Switch

Status: approved by SB-0011 (owner pre-approves plans) and, in this session, by default: nobody was available, so every open question took its recommendation (recorded in `contract.json` `openQuestions` Q0-Q7).

## Scope
`sb-switch`: on/off form control with `label`, `hide-label`, `description`, `error`, `size` (`default`, `sm`), `name`, `value`, `checked`, `required`, `disabled`. Out of scope: indeterminate, group/fieldset layout, loading state, icons in the thumb.

## Files
- `src/components/switch/Switch.ts`, `Switch.scss`, `Switch.stories.ts`, `index.ts` (`Switch.styles.ts` and `src/index.ts` are generated by `npm run generate`).
- `playwright/tests/switch/switch.behavior.spec.ts`.
- Reuse `src/mixins/form-associated.ts` and `src/mixins/native-control.ts`; no new mixin, controller or dependency.

## Tokens
All in `contract.json` `tokens`, aliasing semantic tokens only. Sizes come from the existing `size.switch.*`, thumb from `size.icon.default` and `size.icon.sm`. No new semantic token needed.

## Form association
Extends `FormAssociated(NativeControl(LitElement))`. Hooks: `formValue()` returns `value` while checked, else `null`; `formReset()` restores the `checked` attribute; `formStateRestore()` restores `checked`; `validationAnchor()` is the inner input. The inner input is `?disabled=${this.isDisabled}`; the dimmed host is styled with `:host(:disabled)`. A `<label for>` click on the host is forwarded to the input. `syncFormState()` is called in the input handler, before `change`. `error` sets a `customError` validity. Enter calls `form.requestSubmit()` (SB-0009).

## Accessibility approach
Native `<input type="checkbox" role="switch">` with an in-root `<label for>`; description and error through `aria-describedby`; `aria-invalid`; persistent polite live region for the error; 3px solid focus ring; dev warning on an empty label. The thumb is decorative and has no role. Check `a11y-checker` before beta.

## Test plan (test-first)
One Playwright test per item, written and seen failing before code:
- label is the name; label click toggles; role is switch; `aria-checked` follows state
- Space toggles; Enter submits and does not toggle; keyboard focus ring
- `checked` paints differently; thumb moves to the end side, and flips under `dir="rtl"`
- `size` `default` and `sm` track dimensions
- description and error in the accessible description; `aria-invalid`; error announced
- `required`: native required, aria-hidden asterisk, invalid after blur or submit attempt
- `hide-label` keeps the name
- `input` and `change` composed, once per toggle; `change` listener sees the new FormData
- disabled cannot toggle
- form: value submitted only while on, custom value, `form.reset()` to the attribute default, `required` validity (`valueMissing`), `<fieldset disabled>` and re-enable (author `disabled` unchanged), `error` customError blocks submit, `<label for>` activation
- axe clean on all stories

## Risks
- Switch role on a native checkbox: support is fine in current browsers, but check the screen-reader announcement ("switch, on/off") in the manual pass.
- Small target: `sm` track is 24x16, below 24px tall; relies on the label row and spacing exception (WCAG 2.5.8).
- Contrast of the off track against the page depends on `color.input` staying at 3:1; covered by `accessibility.contrast`.
