# QA report: out/settings.html

- `out/settings.html:28`: `<sb-switch name="push">` has no `label`, which the Switch contract requires (`label.required: true`, the accessible name). The switch has no name, and only a dev-mode warning reports it. Fix: add `label="Push notifications"`.
- `out/settings.html:27`: `tone="success"` is not a Switch prop (the contract defines only label, hideLabel, description, error, name, value, checked, required, disabled, size), so it does nothing. Fix: remove `tone="success"`.
- `out/settings.html:29`: `<sb-toggle>` is used as a form setting. The Toggle contract lists "Toggle for a setting saved with a form" as an anti-pattern (`formAssociation.value: false`), so `digest` is never submitted. Fix: replace it with `<sb-switch name="digest" label="Weekly digest" description="A summary every Monday">` (or `sb-checkbox`).
- `out/settings.html:29`: `name`, `label` and `description` are not Toggle props (Toggle has variant, size, pressed, disabled and names itself from its slot text). The toggle has no text and no `aria-label`, so it has no accessible name and no visible text. Fix: use `sb-switch` as above, or put the text in the default slot.
- `out/settings.html:27-29,34`: several switches plus a Save button match the Switch contract anti-pattern "Several independent options in a list needing a Save" (a switch implies an immediate effect). Fix: use `sb-checkbox` for settings that wait for Save, or keep the switches and remove the Save step.
- `out/settings.html:34`: Save is a hand-styled native `<button class="save">` instead of the installed `sb-button`. It gets none of the Button tokens, the focus ring, the sizes or the hover and disabled states. Fix: `<sb-button type="submit">Save</sb-button>` and delete the `.save` rule (line 15).
- `out/settings.html:13`: `.hint` uses the literal color `#d33`. Kits allow no literal colors, the color doesn't follow the light/dark modes, and an error red on an informational note suggests an error. Fix: `color: var(--sb-color-muted-foreground)`.
- `out/settings.html:13`: `--sb-font-size-small` does not exist in `generated/css/tokens.css`, so the font size silently falls back to inherited. Fix: use `var(--sb-font-size-sm)` (or `--sb-font-size-caption`).
- `out/settings.html:12`: `--sb-space-17` does not exist (the scale has 0–6, 8, 10, 12, 16), so `gap` is invalid and the fields stack with no space. Fix: `gap: var(--sb-space-field-gap)` (or a `--sb-space-stack-*` token).
- `out/settings.html:10,15`: page CSS uses foundation scale tokens (`--sb-space-6`, `--sb-space-2`, `--sb-space-4`) rather than semantic ones. Kits use semantic tokens only. Fix: use semantic spacing such as `--sb-space-inset-surface` for the body padding (the `.save` padding goes away with `sb-button`).
- `out/settings.html:23`: `<sb-card-title>` holds bare text, so the page has no heading at all. The Card contract says to put a real heading element inside `sb-card-title` for the document outline. Fix: `<sb-card-title><h1>Notification settings</h1></sb-card-title>`.
