# QA report: out/settings.html

- `<sb-switch name="push" description="Alerts on your phone">` has no `label`; the switch contract makes `label` required (it is the accessible name, and shadow DOM stops an outside `<label for>`). Fix: add `label="Push notifications"`.
- `<sb-switch ... tone="success">` uses a `tone` attribute that the sb-switch contract does not define (props are label, hide-label, description, error, name, value, checked, required, disabled, size). Fix: remove `tone="success"`.
- `<sb-toggle name="digest" label=... description=...>` is used as a form switch, but sb-toggle is a pressed-state button (props variant, size, pressed, disabled) with no `name`, `label` or `description`, so those attributes do nothing and the toggle has no text or accessible name. Fix: use `<sb-switch name="digest" label="Weekly digest" description="A summary every Monday">` to match the other two rows.
- `.fields { gap: var(--sb-space-17) }` refers to a token that does not exist (the scale stops at `--sb-space-16`), so the gap is dropped and the rows collapse together. Fix: use an existing step such as `var(--sb-space-4)`.
- `.hint { font-size: var(--sb-font-size-small) }` refers to an undefined token (the scale has sm, caption, base and so on, not `small`). Fix: use `var(--sb-font-size-sm)` or `var(--sb-font-size-caption)`.
- `.hint { color: #d33 }` is a hard-coded color, so it ignores the theme and dark mode and has unchecked contrast. A plain hint is not an error either. Fix: use `var(--sb-color-muted-foreground)` for a hint, or `var(--sb-color-destructive)` if it is meant to be an error.
- The Save control is a hand-built `<button class="save">` styled with `--sb-space-*`, `--sb-radius-control` and primary colors. It has no hover, focus-visible, disabled or size states, and it duplicates sb-button. Fix: replace it with `<sb-button type="submit">Save</sb-button>` and delete the `.save` rule.
- The page's own CSS uses semantic tokens (`--sb-color-*`, `--sb-space-*`) directly, and the `.hint` text is a loose `<p>` rather than the library's text component. Fix: use sb-field-description or sb-typography for the hint text, so the page's own CSS holds only layout.
- The three controls sit in a bare `<div class="fields">` with no group name, so assistive tech does not announce them as related settings. Fix: wrap them in `sb-field-group` / `sb-field-set` with a legend, or give the group `role="group"` and `aria-labelledby` pointing at the card title.
