# QA report: out/settings.html

- Line 28: `<sb-switch name="push">` has no `label`, which the Switch contract makes required (it is the accessible name, since an external `<label for>` can't reach the inner input), so the switch has no accessible name. Fix: add `label="Push"`.
- Line 27: `tone="success"` is not a Switch prop (the contract has label, hide-label, description, error, name, value, checked, required, disabled, size), so it is ignored. Fix: remove `tone`, or add it to the Switch contract first if the design needs it.
- Line 29: `<sb-toggle>` is given `name`, `label` and `description`, but the Toggle contract only has variant, size, pressed and disabled. It is a pressed-state button, not a form field, so `digest` is never submitted and the label and description don't render. Fix: use `<sb-switch name="digest" label="Weekly digest" description="A summary every Monday">`, or put the label text inside `<sb-toggle>` and drop `name` and `description`.
- Line 12: `var(--sb-space-17)` does not exist in `generated/css/tokens.css` (the scale ends at `--sb-space-16`), so the `gap` is invalid and the fields have no spacing. Fix: use an existing token such as `var(--sb-space-4)`.
- Line 13: `font-size: var(--sb-font-size-small)` is not a defined token (the scale has `-sm`, `-caption`, `-body` and so on), so the hint falls back to the inherited size. Fix: use `var(--sb-font-size-sm)` or `var(--sb-font-size-caption)`.
- Line 13: the hint colour `#d33` is a hard-coded literal, which bypasses the tokens. It is also red for a neutral note, which reads as an error and may miss the 4.5:1 contrast ratio on the card background. Fix: use `var(--sb-color-muted-foreground)`, or `var(--sb-color-destructive)` only if it is a real error.
- Lines 15 and 34: the Save button is a hand-styled `<button class="save">` that re-implements `sb-button` and has no hover, focus-visible or disabled styling, so keyboard users get no visible focus. Fix: replace it with `<sb-button type="submit">Save</sb-button>` and delete the `.save` rule.
- Lines 7 and 8: the stylesheet and script load from `node_modules/sketchbook/...`. `sketchbook.js` there is the engine CLI bundle, not the component library (the package's `main` is `./dist/index.js`), so `sb-*` elements may never be defined. Fix: load the project's own build (`../generated/css/tokens.css` and `../dist/index.js` as a module).
- Line 8: the script is loaded without `type="module"`, but the library is an ES module (`"type": "module"`). Fix: use `<script type="module" src="../dist/index.js">`.
- Line 31: the "Changes apply after you save." hint is a bare `<p>` that isn't tied to the form controls. Fix: use the Field or `sb-card-description` pattern, or add an `id` to the hint and reference it with `aria-describedby`.
- Line 20: the `<form>` has no `action`, `method` or accessible name, and nothing handles submit. Fix: add `aria-labelledby` pointing to the card title, and an `action` or submit handler.
- Line 23: the page's only heading is an `sb-card-title`, and the `<title>` repeats it; there is no `<h1>`. Fix: give the title heading semantics (a contract-supported level or slotted `<h1>`), or add `role="heading" aria-level="1"`.
