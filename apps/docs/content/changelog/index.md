## v0.9.0

November 26, 2026

[GitHub release v0.9.0](https://github.com/Davecelot/sketchbook/releases/tag/v0.9.0) · [Tagged source v0.9.0](https://github.com/Davecelot/sketchbook/tree/v0.9.0) · [npm package 0.9.0](https://www.npmjs.com/package/@usesketchbook/cli/v/0.9.0)

### Review check findings in Workspace

Run `npx sketchbook workspace` from your design-system folder to see your brand, components, token overrides, and recorded design sync status. Open **Checks** to run the project's checks. Search or filter the findings, open a reported file in your editor, or print a finding to hand off.

Workspace requires an interactive terminal. For scripts, use `npx sketchbook status --json` or `npx sketchbook check --json`.

The [Workspace verification record](https://github.com/Davecelot/sketchbook/blob/v0.9.0/docs/research/workspace-verification-2026-11-26.md) describes the local candidate tests on macOS, including terminal resizing, large reports, and the Unicode search regressions.

### Upgrade an existing project

From your design-system folder:

```sh
npm install -D @usesketchbook/cli@0.9.0
npx sketchbook upgrade --dry-run
```

Review the Sketchbook-owned files in the preview. Apply the upgrade with `npx sketchbook upgrade`, then run `npx sketchbook check`. See the [upgrade guide](https://sketchbook-docs.vercel.app/guides/adopt-in-app/#upgrade) for what the upgrade preserves.

## v0.8.0

November 25, 2026

[GitHub release v0.8.0](https://github.com/Davecelot/sketchbook/releases/tag/v0.8.0) · [Tagged source v0.8.0](https://github.com/Davecelot/sketchbook/tree/v0.8.0) · [npm package 0.8.0](https://www.npmjs.com/package/@usesketchbook/cli/v/0.8.0)

### Keep track of complex component work

Ask your coding agent to use the shared task board in `component-builder` when you start a new composite component or a substantial edit. The Markdown board records who owns each task, what is blocked, and which revision the verification applies to. It does not replace contract approval, test-first evidence, or a formal Review Rangers verdict. Routine work and the CLI are unchanged.

If you already have the skill, update the CLI to `0.8.0`, then preview the module update with `npx sketchbook harness add component-builder --dry-run`. Review any conflicts with team-customized guidance before applying the update.

In the [pilot](https://github.com/Davecelot/sketchbook/blob/v0.8.0/docs/research/component-task-board-pilot.md), a from-scratch Action Toolbar reached the readiness gate after both reviewers rechecked the refreshed evidence. The pilot did not establish a speed gain. The toolbar was a test fixture, not a new library component.

## v0.7.0

November 24, 2026

[GitHub release v0.7.0](https://github.com/Davecelot/sketchbook/releases/tag/v0.7.0) · [Tagged source v0.7.0](https://github.com/Davecelot/sketchbook/tree/v0.7.0) · [npm package 0.7.0](https://www.npmjs.com/package/@usesketchbook/cli/v/0.7.0)

### Rename several semantic tokens together

Use `npx sketchbook tokens rename --map token-renames.json --dry-run` to review names, affected files, CSS changes, and the proposed decision record before applying a batch. Start with your own list, or ask the On-role colors preset to suggest names such as `color.on-primary` for paired foreground colors:

```sh
npx sketchbook tokens rename-plan --preset on-role-colors --out token-renames.json
npx sketchbook tokens rename --map token-renames.json --dry-run
```

The preset writes an editable list. It does not rename tokens or overwrite an existing list. When the preview looks right, run the rename without `--dry-run`, then run `npx sketchbook check`. If a name collides or a check fails, the batch is not applied.

### Choose names at your own pace

Keep Sketchbook’s defaults, bring names your team already uses, or explore alternatives on a real component. The glossary explains distinctions such as a momentary press versus a lasting selection. Guided onboarding makes the naming choice optional; CLI setup still runs without a prompt.

When you start from imported tokens, setup now tells you where to review the proposal and gives you a copyable preview command. Importing maps values. It does not rename tokens.

### Upgrade an existing project

From your design-system folder:

```sh
npm install -D @usesketchbook/cli@0.7.0
npx sketchbook upgrade --dry-run
```

Review the files Sketchbook would update before running `npx sketchbook upgrade`. Upgrading does not change your token names. You can still rename a single token with `npx sketchbook tokens rename <old> <new>`.

## v0.6.1

November 24, 2026

[GitHub release v0.6.1](https://github.com/Davecelot/sketchbook/releases/tag/v0.6.1) · [Tagged source v0.6.1](https://github.com/Davecelot/sketchbook/tree/v0.6.1) · [npm package 0.6.1](https://www.npmjs.com/package/@usesketchbook/cli/v/0.6.1)

Import Tokens Studio themes without picking up disabled sets, and trust your Git hooks to stop when a Sketchbook check cannot finish.

### Fixes

- `sketchbook tokens import` now ignores sets that no theme enables and uses set order for competing values within each theme. If you generated a proposal from a file with disabled sets, regenerate it and review the mappings before applying it.
- The shipped Git hooks now stop on unexpected build or check failures. Checks that pass with recorded token overrides still allow commits and pushes.
- Sketchbook checks reject malformed canonical state keys and duplicate preferred components in the API vocabulary. The reference contracts show the same lifecycle status in Markdown and JSON; checks warn about an existing mismatch in team-owned Markdown.
- The new-component workflow separates registry registration from approval and previews the scaffold before writing it. `sketchbook propagate` points you to the next check instead of asking you to run Figma steps when no sync target is configured.
- The Hammock component audit no longer flags Storybook entry points or generated styles as unused modules. It still reports leads for manual review, not proof of dead code.

### Update an existing project

From your design-system folder:

```sh
npm install -D @usesketchbook/cli@0.6.1
npx sketchbook upgrade --dry-run
npx sketchbook upgrade --yes
npx sketchbook check
```

Review the preview before applying the upgrade. It refreshes Sketchbook-owned files such as the shipped Git hooks; it does not rewrite your component contracts or replace a Git hook your app manages separately. See the [upgrade guide](https://sketchbook-docs.vercel.app/guides/adopt-in-app/#upgrade) for details.

## v0.6.0

November 23, 2026

[GitHub release v0.6.0](https://github.com/Davecelot/sketchbook/releases/tag/v0.6.0) · [Tagged source v0.6.0](https://github.com/Davecelot/sketchbook/tree/v0.6.0) · [npm package 0.6.0](https://www.npmjs.com/package/@usesketchbook/cli/v/0.6.0)

Record component approvals and test-first work with the Sketchbook CLI, whether or not you use a coding agent.

### Record approvals and test runs

- Approve the current contract and plan with `sketchbook approve`. Check C4 reports when the approval no longer covers the current scope. Recorded token renames and prefix changes preserve approval; material changes need fresh approval.
- See the before-and-after changes for wording-only carries with `sketchbook approve --review`, even after a commit. A person can confirm the batch only if every carry still matches the current scope.
- Record failing and passing behavior runs with `sketchbook evidence red` and `sketchbook evidence green`. `sketchbook evidence ready` checks that the passing run is current. A missing browser or Storybook server records nothing.

The records don’t authenticate the approver or tell you why a test failed. Plans marked `test-first: unverified (pre-record)` don’t verify the order of earlier work. See [approval and test-first checks](https://sketchbook-docs.vercel.app/concepts/checks/#gates).

### Fixes

- Prefixes such as `team2` now pass contract validation for components and their sub-elements.
- On a phone, you can tap anywhere in a Docs navigation row to open the link.

### Update an existing project

```sh
npm install -D @usesketchbook/cli@0.6.0
npx sketchbook upgrade --dry-run
npx sketchbook upgrade
npx sketchbook check
```

Review the preview before applying the upgrade. It can add the stub test hook to a compatible Playwright fixture without replacing your other changes. If the fixture has been rewritten, Sketchbook leaves it alone and reports what to do.

## v0.5.0

November 22, 2026

[GitHub release v0.5.0](https://github.com/Davecelot/sketchbook/releases/tag/v0.5.0) · [Tagged source v0.5.0](https://github.com/Davecelot/sketchbook/tree/v0.5.0) · [npm package 0.5.0](https://www.npmjs.com/package/@usesketchbook/cli/v/0.5.0)

Sketchbook v0.5.0 adds a portable catalog of agent workflows. Install what you need without choosing an AI client or model.

- Run `npx sketchbook harness` and choose **Install recommended** for the four default modules, or **Customize installation** to pick individual skills, rules, and commands. The keyboard checklist keeps selections when you filter and previews everything together before writing.
- Skills install as complete modules. Hammock includes its project settings and audit script; Review Rangers includes its reviewer briefs. Older config and brief IDs still work with `harness show`, which points to the owning module, but no longer install independently.
- The installer keeps existing project settings and doesn't activate hooks. A changed install plan requires a fresh confirmation, and a failed install rolls back its own writes without discarding concurrent edits.
- Client profiles still control discovery and optional automation. Claude Code retains its staged native integration. Use `harness list`, `show`, and `add` with `--json` for scripts.

To update an existing project, run `npm install -D @usesketchbook/cli@0.5.0` from your design-system folder. Preview changes with `npx sketchbook upgrade --dry-run`. If the preview looks right, apply it with `npx sketchbook upgrade --yes`, then run `npx sketchbook check` to verify the project. See the [upgrade guide](https://sketchbook-docs.vercel.app/guides/adopt-in-app/#upgrade) for details. For a new project, follow the [Quickstart](https://sketchbook-docs.vercel.app/start/quickstart/). See the [Harness catalog](https://sketchbook-docs.vercel.app/harness/) for install options and Hammock configuration.

## v0.4.1

November 21, 2026

[GitHub release v0.4.1](https://github.com/Davecelot/sketchbook/releases/tag/v0.4.1) · [Tagged source v0.4.1](https://github.com/Davecelot/sketchbook/tree/v0.4.1) · [npm package 0.4.1](https://www.npmjs.com/package/@usesketchbook/cli/v/0.4.1)

Sketchbook v0.4.1 fixes starter updates and catalog restores without changing the CLI workflow.

- Failed `sketchbook init --start` changes in an existing project now leave files and uncommitted edits intact, including when brand options are supplied in the same command.
- Removing a kit from the catalog source keeps a restore copy without reporting the expected catalog mismatch as a failed removal. Other check failures still surface.
- Reinstalling a component or kit from the local source catalog no longer replays token renames the catalog already includes. Downstream installs still apply their rename history.
- A focused browser test run now checks size and motion behavior with alternate brand token values.

For an existing project, install with `npm install -D @usesketchbook/cli@0.4.1`. For a new project, follow the [Quickstart](https://sketchbook-docs.vercel.app/start/quickstart/).

## v0.4.0

November 21, 2026

[GitHub release v0.4.0](https://github.com/Davecelot/sketchbook/releases/tag/v0.4.0) · [Tagged source v0.4.0](https://github.com/Davecelot/sketchbook/tree/v0.4.0) · [npm package 0.4.0](https://www.npmjs.com/package/@usesketchbook/cli/v/0.4.0)

Sketchbook v0.4.0 shares the contract-author and component-builder workflows across agent profiles, without requiring a specific client or model.

- Agent profiles install the same two Agent Skills. Claude Code keeps native wrappers and its existing hooks; core-only projects still work without an agent.
- Contract scaffolding and the Docs explain the same planning and test-first gates across clients. The compatibility map distinguishes documented support, tested client behavior, and unverified real-model behavior.
- Checkout guidance no longer directs agents to the init-generated inventory, and doctor no longer mistakes the source checkout’s Copilot guidance for an installed profile.

Install with `npm install -D @usesketchbook/cli@0.4.0`. In an existing Sketchbook project, preview `npx sketchbook init --dry-run` before installing missing skills; `npx sketchbook upgrade` refreshes harness-owned files. Team-owned guidance is preserved.

[Quickstart](https://sketchbook-docs.vercel.app/start/quickstart/) · [Agent compatibility](https://sketchbook-docs.vercel.app/concepts/agent-compatibility/) · [npm package](https://www.npmjs.com/package/@usesketchbook/cli/v/0.4.0)

Sketchbook v0.3.0 brings the CLI, Docs, and project examples into the same voice.
