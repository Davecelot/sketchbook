# Rule: test-first (features.testFirst = true)

Components are built test-first. For every component, in this order:
1. The contract passes `npm run check` and its `plan.md` is approved (planning gate; check C4 verifies the approval record).
2. Write the story file and the behavior spec `playwright/tests/<name>/<name>.behavior.spec.ts` from the contract: one test per prop, state, keyboard binding, event, form behavior and accessibility rule (name, description, invalid, axe). Use the `playwright-worker` skill and the helpers in `playwright/helpers/`. When the contract binds keys beyond Tab and Enter, the spec also has a "screen-reader view" test that presses them and calls `expectScreenReaderView` (check S1). The story views are generated by `tests/screen-reader`; review them before keeping them (SB-0113).
3. Run `sketchbook evidence red <name>` to record a failing run and move from `test` to `implement`. Confirm that the new tests fail for the intended reason, not a typo or a broken story. If you need the failure details, run `npm run test:component -- tests/<name>`. A missing browser or server records nothing.
4. Implement the smallest code that makes the tests pass. Do not edit tests to fit the code; if the contract was wrong, change the contract first and say so.
5. Green: run `sketchbook evidence green <name>` with the same spec and test setup as red, then `npm run check`, `npm run typecheck`, and `npm run test:component`. If the spec or test setup must change, first record red again against the pre-change implementation. Refactor with the tests green and re-record green if the implementation changed. After review, run `sketchbook evidence ready <name>` before moving the status to `beta`.
